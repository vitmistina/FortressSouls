# R2.1-001: Current-scene extraction evidence

**Status:** Partial evidence accepted for application-side release; production Lua promotion authorized with follow-up validation  
**Date:** 2026-07-16  
**Scope:** Evidence-only DFHack research; no production Lua or backend adapter changes

## Research command

The evidence-only command is:

```text
fortress-souls/research-current-scene
```

The source is retained at:

```text
dfhack/scripts/fortress-souls/research-current-scene.lua
```

It accepts only `scan-units`, `find-sheltered`, `find-features`, `find-stairs`,
`scan-inventory-modes`, `unit <unitId>`, and `point <x> <y> <z>`. It does not write files, invoke
commands, modify the UI, or call mutation helpers. It bounds local extraction
to 33 x 33 cells, site extraction to 24 x 12 cells, and surface candidates to
16 columns.

The broad research scans are not production scene payloads; the retained

## Results

### Environment flags

- Outdoor dwarf `6597` at `(70,85,173)`: `outside=true`, `light=true`,
  `subterranean=false`, classified as `outdoor`.
- Sheltered tile `(40,4,176)`: `outside=false`, `light=true`,
  `subterranean=false`, classified as `sheltered`.
- Underground creature `6614` at `(35,38,26)`: `outside=false`,
  `light=false`, `subterranean=true`, classified as `underground`.
- Active-unit scan found 18 outdoor and 25 underground units. It found no
  active sheltered unit; the sheltered evidence is currently a tile probe.

The source of truth for all classifications is
`dfhack.maps.getTileFlags(pos)`. No visual inference is used.

### Wagon identification

The embark wagon was found at `(70,86,173)` as building type `Wagon` (DFHack
building type `32`). The candidate is obtained through
`dfhack.buildings.findAtTile(pos)` and the typed `df.building_type` enum.

### Inventory exclusion

The outdoor local sample contained 172 in-bounds items:

```text
contained items:          54
inventory-referenced:     56
remaining loose candidates: 62
```

The arithmetic is exact. Contained items are identified with
`dfhack.items.getContainer(item)`. Worn items are identified by matching item
IDs against nearby `unit.inventory` entries; the retained sample records mode
`Worn`. A held-item case was not present in this save, so held-item behavior
still needs a live sample before promotion.

### Hidden cells and map edges

- Outdoor local sample: 373 hidden cells; site sample: 81 hidden cells.
- Underground local sample: all 1,089 cells hidden; site sample: all 288 hidden.
- Hidden samples retain only `dx`, `dy`, and `visibility=hidden`.
- A `(0,0,173)` edge probe preserved a 33 x 33 output with 289 valid cells and
  800 out-of-map cells.
- All retained scene JSON samples are below the 128 KiB limit.

### Features

The bounded feature scan found water, magma, tree/plant tiles, ramps, walls,
and buildings. It found no stair tile in the current save. A full-resolution
stair scan inspected 7,151,616 tiles in 18,263 ms and returned no match.

### Surface candidates

The probe compared five read-only candidates. In the outdoor sample,
`topmostValid`, `firstRevealed`, and `firstOutside` selected open space at
`z=193`, while `firstNonOpenRevealed` selected a revealed floor or ramp around
`z=173/174`. This makes `firstNonOpenRevealed` a candidate for further review,
not an approved production algorithm. The candidate must still be tested at
map edges, overhangs, and multiple biome/terrain cases.

### Repeatability and timing

Three consecutive outdoor calls produced these elapsed times:

```text
80 ms, 89 ms, 95 ms
```

All three outputs were 55,184 bytes in the PowerShell capture and had the same
SHA-256 after removing only the volatile `gameTime` field:

```text
07378E2BEE4A71003E4BDB7AD1072D4E51153DA62E73C75EB631BB2E8A50806A
```

Before and after diagnostics both reported `worldLoaded=true`,
`mapLoaded=true`, and `siteLoaded=true`. No UI API or mutation helper was
invoked. Terminal evidence cannot independently prove the camera position was
unchanged; that remains a manual visual check.
